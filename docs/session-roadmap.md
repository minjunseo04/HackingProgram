# 세션별 개발 로드맵

**기준일:** 2026-11-10

**작업 원칙:** 한 세션은 사용자에게 확인 가능한 제품 단위로 끝낸다. 계획만 세우고 멈추지 않고, 바로 다음 세션의 구현을 진행한다.

## 세션 0 — 배포와 업데이트 경로

**상태: 완료.** 수동 업데이트 확인·파일 검증·교체 흐름을 만들고, v0.2.0까지 GitHub Release에 게시했다. 태그마다 GitHub Actions가 Windows 패키지를 빌드한다. 사용자 PC에서 앱 내 업데이트 확인을 누르는 동작은 별도 사용성 확인 항목이다.

## 세션 1 — 테스트 신원과 권한 규칙

**상태: 완료·공개 (v0.2.0).** 테스트 신원(이름·조직·역할)을 관리하고, 요청을 복제해 신원별로 나눈 뒤 `허용/거부/미지정` 기대값을 저장한다. 기존 저장 자료를 읽을 수 있고, 신원 변경은 로컬 프로젝트 파일에 유지된다. 신원 삭제 시 연결된 규칙은 미지정 상태로 초기화한다. 인증 비밀은 입력하거나 저장하지 않는다.

**완료 기준:** 여러 신원을 만들고 수정·삭제할 수 있고, 요청마다 다른 신원과 기대값을 지정할 수 있으며, 앱을 다시 열어도 선택이 유지된다. 화면은 어떤 규칙이 아직 신원 미지정인지 분명하게 보여준다.

**구현 결과:** 신원 관리 창, 요청 복제 버튼, 요청 표의 테스트 신원 선택란, 로컬 저장 호환을 추가했다. 컴파일은 경고·오류 없이 끝났다. 실제 Windows 화면 조작과 앱 재실행 저장 확인은 아직 사용자가 실행해 볼 항목이다.

## 세션 2 — 로컬 안전 실행

**상태: 완료·공개 (v0.3.0).** 프로젝트 입력과 분리된 내장 로컬 fixture에서 Acme/Birch 가상 계정으로 GET만 실행한다. 안전 모드와 교차 조직 접근을 허용하는 취약 모드를 따로 실행한다. 임시 포트의 `127.0.0.1`에만 바인딩하고 리디렉션·프록시를 사용하지 않는다. 실제 사용자 프로젝트·저장 신원·대상 주소는 읽지 않는다.

소유자 대조 요청이 성공한 경우에만 다른 계정의 401/403/404를 차단 결과와 비교한다. 대조 요청도 404라면 데이터 존재를 확인할 수 없어 판정을 보류한다. 응답 본문은 결과에 표시하거나 파일에 저장하지 않는다.

**완료 기준:** 안전 예제에서 소유 계정 허용·교차 조직 차단이 기대와 일치하고, 없는 자료는 판정 보류로 표시된다. 취약 예제에서 교차 조직 읽기는 검토 대상으로 표시된다. 컴파일은 경고·오류 없이 완료했고 Windows ZIP을 생성했다. 실제 Windows UI 실행 확인은 사용자가 해볼 항목이다.

## 세션 3 — 결과와 증거 보고서

**상태: 완료·공개 (v0.4.0).** 안전·취약 예제 결과를 사용자가 선택한 위치에 JSON 보고서로 저장하고 다시 연다. 보고서는 검사 항목, 신원, 경로, 기대 접근값, 실제 HTTP 상태, 소유자 대조 상태, 판정 이유, 실행 시각, 앱 버전, 검사 범위와 미검사 항목을 담는다.

응답 본문과 사용자 프로젝트 자료는 저장하지 않는다. 파일은 수정 가능한 요약이며 변조 방지 서명은 없다.

**완료 기준:** 사용자가 저장한 보고서를 다시 열어 검토할 수 있고, 검사한 내용과 검사하지 않은 내용을 구분한다. 앱 화면에서 실제 저장·열기를 확인하는 사용성 검수는 남아 있다.

## 세션 4 — 제한된 쓰기 검사

**상태: 완료·공개 (v0.5.0).** 기본 꺼짐인 앱 설정, 예제 창의 실행별 동의, 실행 버튼을 누른 뒤의 최종 확인을 모두 요구한다. 고정된 PATCH 요청은 임시 `127.0.0.1` fixture의 Acme/Birch 가상 문서 라벨만 바꾸며, fixture 종료 때 메모리 값이 사라진다. 안전 예제와 교차 조직 쓰기를 허용하는 취약 예제를 각각 비교하고 JSON 보고서에 결과를 남긴다. v0.4.0 보고서도 계속 열 수 있다.

**완료 기준:** 기본값에서 쓰기 요청을 보내지 않는다. 앱 설정, 실행별 동의, 마지막 확인을 모두 통과해야 고정된 fixture PATCH를 보내며, 저장 프로젝트·사용자 대상 주소에는 연결하지 않는다. UI에서 설정·동의를 실제로 눌러보는 검수는 아직 남아 있다.

**후속 UI 수정 (v0.5.1):** 사용자가 발견한 안내문 잘림을 고쳤다. 안전 안내 영역을 넓히고 쓰기 동의 상태 문구를 명시적으로 두 줄로 표시한다. 빌드된 앱에서 전체 안내가 보이는 것을 확인했다.

## 세션 5 — 사용자 사용성 확인

사용자가 본인 프로젝트에서 먼저 써보고, 학교 지인에게 설치·요청 가져오기·신원 지정·결과 읽기를 부탁한다. 관찰한 혼란과 막힘을 기준으로 한 번에 묶어 개선한다.

**완료 기준:** 실제 사용으로 확인한 문제와 해결을 기록한다. 이 결과는 사용성 근거로만 보고, 시장 수요나 결제 의사로 과장하지 않는다.

## 세션 6 — 승인된 스테이징 환경 연결

실제 사용자 앱을 검사하려면 테스트 범위 확인, 안전한 인증 비밀 보관, 요청 제한, 중단 방법을 먼저 설계한다. 소유하거나 명시적으로 승인받은 대상만 지원한다.

**완료 기준:** 한 개의 승인된 앱에서 범위가 제한된 파일럿을 재현할 수 있다. 이 세션 전에는 고객 앱에 연결하지 않는다.

## 뒤로 미룬 항목

- 영어 등 두 번째 언어 번역이 완성될 때까지 언어 선택 UI를 넣지 않는다.
- 원격 분석·계정·클라우드 저장이 생기기 전에는 정보 수집 동의를 받지 않는다. 업데이트 확인은 사용자가 시작하기 전에 GitHub 연결 정보를 알린다.
- 전체 DAST, 임의 외부 호스트 검사, 자동 권한 추론, 유료 기능은 초기 안전한 흐름이 확인될 때까지 범위 밖이다.

현재 작업의 세부 결과는 [프로젝트 현황](project-status.md), 버전별 변경은 [변경 기록](../CHANGELOG.md)에 남긴다. v0.5.0은 GitHub Release에 게시했고 v0.5.1 UI 수정판을 게시 중이다.

# 프로젝트 현황

**기준일:** 2026-11-10

**제품명:** 미정

**상태:** v0.5.0 공개 완료. GitHub Actions Windows x64 패키지 빌드가 성공했다. 설정·동의 흐름과 제한적 쓰기 화면의 직접 사용성 확인은 아직 남아 있다.

## 한 문장 설명

앱 제작자가 납품 전 여러 테스트 계정으로 같은 API 작업을 확인하고, 조직·역할 사이의 접근 경계가 지켜지는지 근거 보고서로 검토하도록 돕는 도구를 구상한다.

## 정한 방향

- Supabase 전용이 아닌 스택 중립 제품으로 본다. 첫 지원 방식은 실제 고객의 작업 흐름을 확인한 뒤 고른다.
- 초기 문제는 IDOR/BOLA, 역할 권한 상승, 테넌트 간 접근이다.
- 잠정 고객은 앱을 반복 납품하는 소규모 제작사와 프리랜서다. 이 타깃과 반복 수요는 아직 확인되지 않았다.
- 제품은 앱의 권한 의도를 자동으로 안다고 주장하지 않는다. 사람의 기대 규칙을 입력받아 테스트 계정 간 결과를 비교하는 방향이다.
- 외부에 데모를 보여주는 일은 사용자가 보류했다. 현재 정적 데모는 내부 설명용 시뮬레이션이며 실제 검사 결과가 아니다.
- 웹사이트는 설명과 프로그램 다운로드만 제공한다. 프로젝트와 테스트 자료 처리는 설치형 프로그램 안에서 한다.
- 사용자는 학교 프로젝트 진행 중 본인이 먼저 써보고 다른 사람에게도 사용 테스트를 부탁할 계획이다. 이는 사용성 피드백이며, 실제 제작자 구매 수요나 지불 의사 확인과는 별개다.
- AI 페르소나 10명은 가설을 반박해 보는 용도다. 실제 인터뷰·고객 수요·결제 의사 근거로 취급하지 않는다.
- 단건 $19, 월 $49(5개 프로젝트), 추가 프로젝트 월 $9는 임시 가격이며 검증되지 않았다.

## 완료된 기술 작업

- 로컬 API fixture와 다중 신원 권한 검사 PoC: 기본 읽기 검사, 테넌트·역할 경계, opt-in 된 제한적 fixture 쓰기 검사.
- HAR와 OpenAPI 3.0/3.1 JSON에서 GET/PATCH 요청 초안을 생성한다. 결과는 비실행 상태이고 인증 정보·본문·기대 권한 규칙을 자동으로 넣지 않는다.
- 두 importer가 origin·경로 접두사 검증, 민감 경로 가림, 중복 제거를 공통 유틸리티로 사용한다.
- Windows 프로그램 v0.2.0에서 HAR/OpenAPI JSON을 가져와 요청 템플릿을 정리하고, 테스트 신원별 기대 접근값을 PC에 저장할 수 있다.
- 업데이트는 사용자가 직접 눌러 확인한다. 연결 전 IP 주소와 앱 버전이 GitHub에 전달될 수 있다고 알리고, 프로젝트 자료는 보내지 않는다.
- 현재 지원 언어는 한국어다. 다른 언어 번역이 제공될 때 언어 설정을 추가한다. 분석 수집은 없으며 업데이트 요청은 사용자가 시작할 때만 보낸다.
- `v0.2.0` 태그 게시와 GitHub Actions Windows 빌드가 성공했고 Release ZIP을 공개했다. 앱에서 최신 Release 확인과 업데이트 파일 검증·교체가 가능하다.
- v0.2.0은 테스트 신원(이름·조직·역할) 관리, 동일 요청 복제, 신원별 기대값 저장을 지원한다. 로그인 비밀번호·토큰은 입력하거나 저장하지 않는다.
- v0.3.0에 내장 안전·취약 예제 실행을 추가하고 GitHub Release에 공개했다. 실행은 고정된 가상 경로·신원만 사용하고 loopback 임시 포트, GET, 프록시·리디렉션 없음으로 제한한다. 사용자 프로젝트나 대상 주소는 읽지 않는다.
- v0.3.0 컴파일은 경고·오류 없이 완료했고 GitHub Actions가 Windows x64 ZIP을 빌드·게시했다. 패키징 중 NuGet 취약점 정보 서버에 연결하지 못했다는 경고가 있었지만 릴리스 빌드는 성공했다. 사용자가 앱에서 예제를 실행해 UI 결과를 확인하는 과정은 남아 있다.
- v0.4.0은 내장 예제 결과를 JSON 보고서로 저장·열기한다. 각 결과의 기대값, 실제 HTTP 상태와 소유자 대조 상태, 판정 이유를 기록하고 검사 범위·미검사 항목·실행 시각·앱 버전을 포함한다. 응답 본문과 프로젝트 자료는 보고서에 포함하지 않는다. 파일은 수정 가능하며 변조 방지 서명은 없다.
- v0.5.0은 고정된 PATCH를 내장 loopback fixture에만 보내는 쓰기 예제를 추가했다. 기본 꺼짐 앱 설정, 실행별 화면 동의, 최종 실행 확인이 모두 필요하다. 별도 Acme/Birch 가상 데이터는 서버 메모리에서만 바뀌고 종료 시 사라진다. 사용자 프로젝트·대상 주소·가져온 요청은 쓰기에 사용하지 않는다.
- 다음 세션은 v0.5.0의 기본 꺼짐 설정과 다중 동의 흐름을 확인한 뒤 사용자 사용성 점검을 진행한다. 세션 순서와 완료 기준은 [세션별 로드맵](session-roadmap.md)에 있다.
- 제품 설명과 다운로드만 제공하는 정적 웹사이트 초안을 만들었다.
- Windows x64 자체 포함 ZIP 패키지를 빌드했다. 프로젝트 소스와 문서는 Git으로 버전을 관리한다. ZIP 같은 빌드 산출물은 Git 이력에 넣지 않는다.
- 검증은 로컬 fixture와 합성 입력에 한정된다. 실제 고객 앱의 정확도, 범용 취약점 탐지, 사업성은 증명되지 않았다.

## 현재 제한

- 검사기는 loopback fixture만 대상으로 한다. 고객 앱이나 인터넷 호스트에 연결하지 않는다.
- 공개 데스크톱 v0.5.0은 내장 예제만 실행하며, 사용자가 가져온 실제 API 요청을 실행하지 않는다. 쓰기는 명시적 동의 후 loopback fixture의 메모리에서만 수행한다. JSON 보고서는 사용자가 선택한 위치에서만 읽고 쓴다.
- 외부 스캔, 자동 크롤링, 전체 DAST, 대시보드, 결제 기능은 아직 제품 범위에 들어 있지 않다.

## 다음 순서

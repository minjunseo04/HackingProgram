# 권한 경계 검증 도구 — 프로젝트 보고서

**작성일:** 2026-11-09  
**상태:** 스택 중립 가설, 로컬 권한 검사 PoC, HAR/OpenAPI 요청 초안 importer 작성 및 fixture 검증 완료  
**제품명:** 미정

## 1. 결정 사항

Supabase에만 한정하지 않는다. 제품 문제를 특정 데이터베이스가 아니라 로그인한 사용자·역할·조직 사이의 접근 경계가 지켜지는지 확인하는 것으로 정의한다. 초기 유스케이스는 다른 사용자의 데이터 열람/수정(IDOR/BOLA), 역할 상승, 테넌트 경계 침범과 같은 권한 오류다.

첫 제품의 핵심은 특정 백엔드 설정을 검사하는 것이 아니다. 사용자가 승인한 스테이징 환경에서 서로 다른 테스트 신원으로 같은 요청을 재실행하고, 사용자가 확인한 기대 접근 규칙과 실제 결과를 비교한다. 결과는 재현 가능한 요청·응답 근거, 검사 범위, 미검사 항목이 담긴 보고서로 제공한다. 제품이 앱의 권한 의도를 임의로 추측하지 않는다.

## 2. 고객과 해결할 문제

### 첫 고객군 가설

- Lovable, Bolt, Cursor 등으로 앱을 여러 개 제작해 고객에게 반복 납품하는 프리랜서
- AI 기반 MVP를 고객사에 반복 납품하는 소규모 제작사
- 프로젝트별 보안 점검 결과를 고객에게 보여줄 필요가 있는 개발 컨설턴트

### 고객의 현재 불편에 대한 가설

- RLS가 활성화되어 있어도 정책이 과도하게 허용할 수 있다.
- 정책 메타데이터를 읽는 것만으로 실제 사용자 간 분리를 증명하기 어렵다.
- Supabase 문서는 사용자 역할별로 정책을 시험하고, 서로 다른 사용자의 데이터 접근을 확인하는 절차를 안내한다.
- 매 프로젝트마다 테스트 준비와 결과 설명을 반복하면 납품 시간과 신뢰에 비용이 든다.

이 가설은 공개 문서와 제품 설명에서 도출한 것이다. 실제 제작사의 반복 비용이나 구매 의사는 아직 확인되지 않았다.

## 3. 경쟁 현황과 기회

AI 앱 보안 스캐너는 이미 존재한다. VibeLocked는 무료 기능과 월 $15 모니터링을, Vibe App Scanner는 월 $19 및 $39 플랜을 공개한다. VibeSafe는 일회성 스캔과 월 $39 모니터링, 별도의 $399 수동 침투 테스트를 제시한다. Lovable도 게시 시 기본 보안 검사와 요청형 심층 검사를 제공한다.

따라서 “취약점 여러 개를 찾아주는 대시보드”로는 차별화가 어렵다. ZAP도 인증된 앱과 API 스캔을 지원한다. 이 프로젝트의 차별화 가설은 **사용자가 기대 규칙을 지정하고, 여러 신원으로 같은 동작을 실행해 권한 경계가 지켜지는지 확인하며, 제작사가 고객에게 제출할 증거 보고서를 만드는 간단한 흐름**이다. 이 가설은 아직 검증되지 않았다. Supabase는 첫 어댑터 후보 중 하나일 뿐 제품의 한계로 고정하지 않는다.

## 4. 임시 가격 가설

가격은 요청에 따라 임의로 시작값을 정한 것이며, 시장에서 검증된 가격이 아니다.

| 요금 | 임시 가격 | 포함 범위 |
|---|---:|---|
| 단건 점검 | $19 | 승인된 앱 1개, 결과 보고서 1회 |
| 제작사 초기 플랜 | $49/월 | 고객 프로젝트 5개, 재검사, 브랜딩 가능한 보고서 |
| 추가 프로젝트 | $9/월 | 활성 고객 프로젝트 1개당 |

경쟁 제품의 저가 플랜과 비교해 진입 가격을 낮게 잡았다. 실제 지불 의사는 페르소나 응답이 아니라 실제 파일럿 결제로 확인한다.

## 5. AI 가상 페르소나 10명 검토 — 스택 중립 권한 테스트 제품

사용자가 실제 인터뷰 참여자를 구하기 어려운 상황을 반영해, 서로 다른 앱 제작·구매 유형 10명을 대상으로 가상 인터뷰를 다시 구성했다. 각 인물은 사업 가설에 반대할 수 있도록 구매 대안과 지불 장벽도 함께 평가했다. **아래 답변은 AI가 만든 시뮬레이션이며 실제 사람의 발언·인터뷰·구매 의향이 아니다.**

| # | 가상 인물 | 가상 반응 | 구매 장벽 / 시뮬레이션에서 나온 요구 |
|---:|---|---|---|
| 1 | 한 달에 AI 기반 내부 도구·고객 앱 2~3개를 납품하는 3인 개발 스튜디오 대표 | 가장 높은 적합 가설 | 고객 납품 전 권한 확인과 보고서가 반복된다면 $49/월 검토 가능. 단, 매 앱마다 로그인 설정을 새로 하게 만들면 사용 안 함. |
| 2 | Lovable·Bolt로 소상공인 MVP를 만드는 독립 제작자 | 조건부 적합 | 보안 전문 지식 없이 체크할 수 있어야 함. 고객이 보안 보고서를 요구하지 않는 프로젝트에서는 $19도 안 낼 수 있음. |
| 3 | Firebase와 Next.js를 쓰는 프리랜서 | 조건부 적합 | Supabase 고정이면 제외. HTTP 요청을 쉽게 가져오고 테스트 계정을 비교할 수 있으면 데모는 보겠지만, 자주 납품하지 않아 구독보다 단건 선호. |
| 4 | Bubble 기반 업무 앱 제작 에이전시 | 낮음~조건부 | 데이터 규칙은 중요하지만 브라우저 UI에서 이미 테스트함. API 호출/권한 케이스를 자동으로 만들지 못하면 새 도구를 더할 이유가 약함. |
| 5 | 유료 SaaS를 운영하는 2인 창업자 | 단건 가능성 | 출시 전 한 번은 고려할 수 있으나, 자체 테스트나 외부 침투 테스트와 비교해 왜 필요한지 분명해야 함. 월 구독은 낮은 선호. |
| 6 | 백엔드 테스트와 CI를 이미 운영하는 숙련 엔지니어 | 낮은 적합 | 코드 테스트로 충분하다고 봄. 기존 테스트가 못 잡은 실제 권한 사고를 재현하거나 설정 비용을 줄인다는 증거가 있어야 전환. |
| 7 | 보안 컨설턴트/침투 테스트 담당자 | 구매자보다는 검토자 | 자동 결과를 그대로 믿지 않음. 요청·응답 근거, 재현성, 오탐 통제가 없으면 보고서가 오히려 위험. 전문 테스트를 대체한다고 주장하면 거부. |
| 8 | AI 앱을 만들었지만 고객 납품 경험이 없는 초보 빌더 | 낮은 적합 | 관심은 있어도 지불 능력과 반복 사용이 낮음. 무료 도구나 빌더 내장 검사를 먼저 씀. 초기 타깃으로 삼지 않는 편이 낫다. |
| 9 | 개발자를 고용하는 비기술 소기업 대표 | 낮음 | 구매 결정권은 있을 수 있지만 테스트 설정을 직접 못 함. 개발자나 컨설턴트가 결과를 제출하는 형태가 아니면 사용하기 어려움. |
| 10 | 고객사 납품을 늘리려는 소규모 에이전시 운영자 | 가장 높은 적합 가설 | 테스트 자체보다 납품 전 체크리스트와 고객에게 설명 가능한 증거가 가치. 프로젝트마다 재사용되고 사고 책임을 줄인다는 체감이 있어야 월 결제. |

### 모의 패널 판정

- **조건부 진행:** 권한 테스트라는 문제는 여러 스택에 공통으로 존재할 수 있지만, 구매 가능성이 높아 보이는 가설 고객은 앱을 반복 납품하는 소규모 제작사다.
- 초기 제품은 “모든 취약점을 찾는 스캐너” 대신 **납품 전 다중 계정 권한 경계 확인 + 증거 보고서**로 좁히는 편이 낫다.
- $19 단건은 첫 사용 장벽이 낮은 가격 가설이고, $49/월은 한 달에 여러 고객 프로젝트에서 재검사·보고서를 반복해야 설득력이 생긴다. 두 가격 모두 AI 응답만으로 타당하다고 결론낼 수 없다.
- 가장 큰 실패 요인은 고객이 권한 테스트를 충분히 자주 하지 않거나, 기존 수동 테스트·개발자 작성 테스트·보안 도구로 충분하다고 보는 것이다.
- 10명 중 “긍정”이 몇 명인지 수요율로 계산하지 않는다. 페르소나는 시장 크기, 고객 획득 비용, 실제 결제 전환을 측정할 수 없다.

### 이 단계에서 내릴 결정

가상 패널만으로 사업성이 입증됐다고 할 수는 없다. 다만 **Supabase 전용으로 만들지 않고, 납품 전 권한 경계 검증이라는 좁은 문제를 보여주는 샘플 데모까지는 진행할 가치가 있다.** 가상 API로 계정 A/B 결과와 보고서를 보여주는 목업을 만들었다. 실제 반응 전에는 구독형 제품 전체나 다중 스택 지원을 구축하지 않는다.

## 6. MVP 범위 — 스택 중립 가설

### 포함

1. 사용자가 승인한 스테이징 앱에서 브라우저/ API 요청을 확보한다. 첫 입력 방식은 고객 인터뷰 이후 선택한다.
2. 사용자가 테스트 신원, 역할, 자원, 기대 접근 규칙을 지정한다.
3. 선택한 요청을 다른 테스트 신원으로 재실행해 IDOR/BOLA·테넌트 경계 오류의 증거를 찾는다.
4. 요청·기대 결과·실제 결과·검사 범위·미검사 범위를 보고서에 남긴다.
5. 수정 후 같은 시나리오를 다시 실행한다.

### MVP에서 제외

- 임의의 제3자 도메인이나 IP에 대한 스캔
- 운영 데이터베이스에서의 파괴적 테스트
- 포괄적인 침투 테스트, 보안 인증 또는 “안전 보장” 배지
- 모든 프레임워크 및 모든 취약점 유형 자동 지원
- AI가 승인 없이 정책을 자동 변경하거나 배포하는 기능

### 정확성 기준

사용자가 확인한 기대 정책과 테스트 결과를 비교해 보고한다. “발견 사항 없음”을 “앱이 안전함”으로 표현하지 않는다. 테스트 환경, 적용한 역할, 실행한 행위, 미검사 범위를 함께 기록한다.

## 7. 개발 방향

초기 버전은 공통 HTTP 요청 재생과 명시적인 기대 권한 규칙을 중심으로 설계한다. Supabase 등 플랫폼별 연결은 인터뷰에서 실제 사용 비중이 확인된 순서로 추가한다. 소스 코드와 계정 비밀 정보를 중앙 서버에 보관하지 않는 로컬 우선 방식을 우선 검토한다. 지원을 쉽게 만드는 연결 방식은 파일럿으로 확인한다.

보안 검사의 결과가 제품의 핵심이므로, 검사 논리는 일반 생성형 AI 답변에 맡기지 않고 명시적 테스트와 재현 가능한 사례로 구현한다. Gemini Pro와 Codex는 구현 보조에 사용할 수 있지만, 결과 정확성의 보증 수단으로 간주하지 않는다.

## 8. 사업 검증 및 중단 기준

### 첫 파일럿 목표

- 먼저 실제 앱 제작자 3명과 15분 대화 또는 샘플 시나리오 검토를 진행한다. 처음부터 고객 앱 접근이나 비밀 정보를 요청하지 않는다.
- 실제 고객 앱을 반복 납품하는지와 사용 스택을 확인한다.
- 현재 정책 검증에 걸리는 시간, 고객 보고에 쓰는 시간, 실수·재작업 경험을 확인한다.
- 무료 사용 의향이 아니라 임시 가격으로 결제 또는 유료 파일럿 동의를 구한다.

### 계속 개발할 기준

초기 3명 중 2명 이상이 최근 프로젝트에서 겪은 구체적인 권한 검증 문제를 말하고, 적어도 1명이 샘플 시나리오 검토나 승인된 스테이징 파일럿에 참여하면 다음 단계로 간다. 그 뒤 더 넓은 표본에서 유료 의향을 확인한다. 3명은 시장 규모를 증명하는 표본이 아니라 다음 실험의 가치가 있는지 보는 저비용 신호다.

반대로 대부분이 단일 프로젝트 사용자이거나, 기존 빌더·pgTAP으로 해결하거나, 고객 보고에 추가 비용을 내지 않으면 구독형 제품을 중단하고 단건 리포트 서비스 또는 다른 문제로 전환한다.

## 9. 주요 위험

- 잘못된 “통과” 판정은 실제 데이터 노출로 이어질 수 있다.
- 정책 의도를 자동 추정하면 오탐과 누락이 발생한다.
- 기존 빌더 보안 기능과 저가 스캐너가 빠르게 개선되고 있다.
- 개발자 도구 시장에서 좋은 제품도 첫 고객 확보가 어렵다.
- 고객 저장소·자격 증명 접근은 높은 신뢰와 최소 권한 설계를 요구한다.

완화책은 초기 검사 종류를 권한 경계로 좁히고, 승인된 스테이징 환경에서만 시험하며, 보고서에 한계와 근거를 명시하는 것이다. 스택 중립은 모든 플랫폼 지원을 한 번에 만든다는 의미가 아니다.

## 11. 로컬 기술 PoC 진행 상황

2026-11-09 기준, 로컬 전용 GET 및 명시적 fixture PATCH 권한 검사기를 작성했다. 계정별 Bearer/Cookie/custom header를 설정할 수 있고 비밀 헤더는 환경 변수에서 읽을 수 있다. 허용 응답 표식과 거부 응답의 금지 표식을 비교하며, 보고서에는 원본 응답을 저장하지 않는다. 루프백 IP만 대상으로 허용하고 응답 본문 확인은 64 KiB로 제한했다.

로컬 fixture에서 안전한 테넌트 격리와 관리자 권한 시나리오 5건 통과, 교차 테넌트 유출 1건 검토, 403 본문 유출 1건 검토, 역할 검사 비활성화 시 일반 사용자의 관리자 감사 로그 접근 1건 검토를 확인했다. 별도 쓰기 시나리오로 안전 테넌트 쓰기 2건 통과와 일반 사용자의 관리자 자료 쓰기 제한 4건 통과를 확인했고, 의도적 쓰기 권한 우회는 검토로 탐지했다. 존재하지 않는 경로는 소유자 대조 요청이 실패해 차단 성공이 아니라 `inconclusive`로 분류했다. 결과 요약은 `poc/results/`에 저장돼 있다. 이 결과는 제품의 실제 서비스 정확도나 사업성을 검증하지 않는다.

HAR importer와 OpenAPI 3.0/3.1 JSON importer는 선택 origin/경로 접두사에 해당하는 GET/PATCH 템플릿만 출력한다. 헤더·쿠키·쿼리·요청/응답 본문, 명세 설명과 예시는 제외하고 민감해 보이는 경로 조각을 가린다. 결과물은 인증 신원과 기대 권한이 미정인 실행 불가 초안이며, 자동 실행이나 외부 요청은 하지 않는다. HAR는 관찰한 트래픽을, OpenAPI는 명세에만 선언된 경로를 보완적으로 제공한다.

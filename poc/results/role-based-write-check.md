# 역할 기반 쓰기 검사 — 로컬 fixture 결과

## 결과

| 실행 모드 | 통과 | 검토 | 확인 불가 | 의미 |
|---|---:|---:|---:|---|
| 역할 정책 적용 + 명시적 PATCH 허용 | 4 | 0 | 0 | 일반 사용자의 관리자 자료 변경 차단, 관리자의 변경은 허용되고 후속 읽기로 확인 |
| `--role-write-vulnerable` + 명시적 PATCH 허용 | 2 | 1 | 1 | 일반 사용자의 관리자 자료 변경을 검토로 탐지; 후속 원본 제목 확인은 이미 변경되어 확인 불가 |
| 검사기 `--allow-local-writes` 생략 | 1 | 0 | 3 | PATCH 요청 두 건을 보내지 않고 건너뜀 |

## 범위와 한계

- `127.0.0.1` fixture의 감사 로그 제목 변경만 실행
- role-vulnerable 모드도 테넌트 격리는 유지하고 PATCH의 역할 확인만 우회
- 관리자의 허용된 수정과 일반 사용자의 거부된 수정 모두 같은 시나리오에서 확인
- 제목 변경은 프로세스 메모리에서만 유지되며 fixture 서버를 재시작하면 초기화
- 실제 고객 서비스나 실제 계정은 사용하지 않음
- 결과는 fixture 동작 확인이며 범용 앱의 권한 검증 정확도를 입증하지 않음

# HAR vs OpenAPI 시나리오 초안 가져오기 비교

두 importer를 합성 입력으로 실행했다. 두 입력 모두 네트워크 요청을 보내지 않고 실행 불가 초안을 만든다.

| 항목 | HAR | OpenAPI JSON |
|---|---|---|
| 입력이 나타내는 것 | 실제 기록에 등장한 요청 | 명세에 선언된 API operation |
| 합성 입력에서 나온 범위 | 5개 기록 중 선택 origin 4개, `/api/` 3개, 중복 제거 후 GET/PATCH 2개 | 4개 경로 중 `/api/v2/` 아래 GET/PATCH 5개, PUT 1개 생략 |
| 장점 | 실제 호출 형식과 어떤 요청이 관찰됐는지 반영 | 아직 실행되지 않은 선언 경로도 찾을 수 있음 |
| 한계 | 기록되지 않은 기능은 안 보임; HAR 원본에는 비밀값이 들어 있을 수 있음 | 명세가 낡거나 빠질 수 있음; importer는 JSON 3.0/3.1만 읽고 `$ref`/YAML은 처리하지 않음 |
| 민감값 처리 | 헤더, 쿠키, 쿼리, 본문 제외; 민감해 보이는 경로 조각 가림 | 설명, 예시, 보안 정의, 헤더, 본문 제외; 경로 변수와 민감해 보이는 조각 가림 |
| 자동 실행 | 안 함 | 안 함 |

## 판단

둘 중 하나를 승자로 정할 이유는 없다. HAR는 실제 관찰 범위를 주고, OpenAPI는 선언됐지만 캡처되지 않은 경로를 보완한다. 공통 초안 형식으로 합치되, 각 경로·신원·기대 허용/거부 규칙은 사람이 확인해야 한다.

경로 가림은 패턴 기반이라 모든 개인 식별자를 알아낼 수 없다. 원본 HAR와 OpenAPI 파일을 민감 자료로 취급하고, 생성 초안을 실행 전에 사람이 검토해야 한다.

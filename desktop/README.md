# BoundaryCheck Windows desktop app

- 현재 소스 버전: **0.4.0**
- 공개 GitHub Release: **0.4.0**

## 실행

GitHub Releases에서 `BoundaryCheck-win-x64.zip`을 받아 압축을 풀고 `BoundaryCheck.exe`를 실행합니다. Windows x64용 자체 포함 파일이라 별도 .NET 설치가 필요하지 않습니다.

## v0.4.0 기능

- 프로젝트 이름, 대상 origin, API 경로 저장
- HAR 또는 OpenAPI 3.0/3.1 JSON에서 GET/PATCH 요청 경로 가져오기
- 긴 숫자, UUID, 토큰처럼 보이는 경로 조각 가리기 및 중복 요청 합치기
- 이름·조직·역할 기반 테스트 신원 관리
- 같은 요청 경로를 신원별로 복제하고, 각 신원에 기대 접근값(미지정/허용/거부) 지정
- 저장 프로젝트와 분리된 내장 예제의 안전·취약 접근 경계 실행
- 예제별 기대값, 실제 HTTP 상태와 소유자 대조 상태, 판정 이유, 검사 범위를 JSON 보고서로 저장·열기
- 외부 네트워크 차단, 임시 loopback 포트, GET 전용 실행, 응답 본문 미저장
- 작업 내용을 `%LOCALAPPDATA%\BoundaryCheck\project.json`에 저장
- 첫 화면에서 로컬 저장과 원격 전송 여부를 안내
- 화면 배율에 맞춰 창과 입력 영역 크기 조정
- GitHub Releases에서 사용자가 직접 확인하고 승인하는 앱 업데이트

실행 기능은 앱에 내장된 Acme/Birch 가상 예제에만 적용됩니다. 저장 프로젝트, 대상 주소, 가져온 요청, 테스트 신원은 실행에 사용하지 않으며 사용자의 실제 API에는 연결하지 않습니다. JSON 보고서는 사용자가 선택한 위치에 저장하며 요청·응답 본문이나 프로젝트 파일은 포함하지 않습니다. 보고서는 수정 가능한 요약이며 변조 방지 서명을 제공하지 않습니다. 신원은 테스트 계정의 이름·조직·역할 메모이며, 실제 비밀번호·토큰은 입력하거나 저장하지 않습니다. 업데이트 확인은 자동으로 실행되지 않으며, 사용자가 버튼을 누른 뒤 연결 안내를 확인해야 합니다. GitHub는 요청에 사용된 IP 주소와 앱 버전을 볼 수 있지만 프로젝트 자료는 전송하지 않습니다. 현재 지원 언어는 한국어이며, 다른 언어가 실제로 번역되면 언어 설정을 추가합니다. 원격 분석이나 계정 기능은 없습니다.

## 소스에서 빌드

새 버전은 버전을 올리고 `v*.*.*` 태그를 push하면 GitHub Actions가 릴리스 파일을 만듭니다. 현재 공개 Release는 v0.4.0입니다. 앱은 사용자가 **업데이트 확인**을 누른 경우에만 이 저장소의 최신 Release를 확인합니다. GitHub 릴리스 자산의 SHA-256 digest와 다운로드 파일을 대조하고, 성공한 경우에만 현재 폴더의 실행 파일을 교체합니다. 압축을 푼 프로그램 폴더에 쓰기 권한이 필요합니다.

`.NET 10 Windows Desktop SDK`가 필요합니다.

```powershell
dotnet build .\desktop\BoundaryCheck.csproj --configuration Release
```
